SHOCKME

How we built a room that is
confidently wrong about itself.

8,191 lines. Three processes. No build step, no bundler, no framework, no client-side router, and zero runtime dependencies. This is a technical account of thrilling.world — including the five bugs that passed every test in the repository.

Live: thrilling.world

01

What it is

You arrive in a waiting room that is polite, patient, and slightly wrong. It counts chairs incorrectly and will not be persuaded otherwise. Strangers murmur in a sidebar and you cannot tell which of them are real. At the end it hands you a serial-numbered certificate of your visit that names the rooms you never found.

The brief was specific and unusually hard to satisfy: odd and exhilarating at the same time. Addictive yet harmless. A little scary — but not horror. No gore, no threats, no jump scares. Closer to a Borges footnote than a haunted house.

02

The stack

Three processes on one VPS. No orchestrator, no containers, no process manager, no CI. The whole thing is three shell scripts and a git pull.

processwhatport
nedbdnedb-engine 2.8.2 --dag — append-only, hash-linked, content-addressed7070
imaginellama.cpp b10322 · Qwen3.5-0.8B GGUF Q4_K_M · 532 MB · CPU only8081
bffNode 22 with --experimental-strip-types3400

There is no build step. Node strips the TypeScript at load. That flag is required on 22.6–23.5 and removed at 23.6+, which is the kind of detail that costs an hour if it isn't written down — so it's written down, in the run scripts.

Cloudflare Flexible SSL sits in front, terminating at nginx on port 80 only. The box is a Mail-in-a-Box, so nginx wants sites-available plus a symlink, and there is deliberately no https redirect — Flexible mode would loop forever.

The BFF boundary

One module — engine/nedb.ts — is the sole HTTP client for the datastore. Nothing else may speak to it. The browser's entire vocabulary is sceneId, choiceId, dwellMs, a chair count, a sentence, and an email address.

The load-bearing rule

The session seed never crosses the wire. Every random decision — which rooms exist, how many chairs, which stranger speaks — is made server-side from that seed. That is what makes a visit replayable, provable, and impossible to tamper with from the client.

03

Persistence that cannot forget

Twelve collections in NEDB. Nothing is ever updated and nothing is ever deleted — a "change" is a new row whose hash chains to the previous one. verify() walks the entire chain and reports any tampering. 

// 12 collections, append-only, hash-linked
visitors  sessions  experiences  scenes  events
encounters  artifacts  broadcasts  experience_versions
subscribers        ← opt-in PII, deliberately NOT joined to behaviour
sites  pixel_events ← the pixel

// 13 event kinds make up one visit
arrived · choice · dwell · counted · press · said · answered
drawn · sting · echo · recognised · afterimage · arrival_beat

This is not architectural purity for its own sake. It is load-bearing for a joke.

One of the rooms lists everything the system knows about you and offers a button marked Delete it. Press it and the room answers:

It has been deleted. It has also been kept. These are different systems.

That is not a bit. It is a literal, accurate description of the storage engine. The room physically cannot remove a row without breaking the chain — all it can do is append the record of you asking. The architecture wrote the best line in the product.

Two gotchas, encoded so they cannot be re-derived

NQL filters on _id, not id. Getting it wrong returns silent empty results, which had already calcified into local folklore — "TRACE is broken." It isn't. The eq() helper now encodes the correct form so nobody rediscovers the myth.

ensureDatabase() lists before creating, because POST on an already-open database returns 500 locked by another process (pid N) — where N is the daemon itself.

04

Determinism

mulberry32, with namespaced streams. This detail matters more than it looks. 

new Rng(seed, 'floorplan')          // which rooms exist
new Rng(seed, 'room')               // chairs, greeting, apology
new Rng(seed, `sting:${sceneId}`)   // which shock, where
new Rng(seed, `verdict:${guess}`)   // what the room thinks of your count

Without namespacing, adding one new consumer shifts every downstream sequence — and every previously generated room silently becomes a different room. With it, each subsystem draws from its own stream and new features cannot disturb old ones.

Replays derive a provable child: deriveReplaySeed(parentSeed, replayIndex, worldSalt). The child is cryptographically linked to the parent, so a replay can be demonstrated to descend from the original visit rather than merely resembling it.

One deliberate exception: mintToken() is not seed-derived. A share token computable from a seed would let anyone enumerate every artifact ever made.

05

A building that differs per visitor

The front page promises "You didn't find the same website they did." For a while that was true of the words and false of everything else — there was exactly one SCENES array and everyone walked it.

Now planFor(seed, SCENES) returns a mutated copy per visitor.

The prune is the interesting part

The one-way corridor orphans an entire wing. The test caught it instantly — 152 failures, all inventory unreachable / dark unreachable.

The fix was not to weaken the variation. It was to delete the orphans: if no door in your building opens onto the dark, then for you there is no dark. Some visitors genuinely have fewer rooms than others, which is the entire point — and reachability became true by construction rather than by careful authoring.

The retention mechanic

The best possible single run sees 8 of 12 rooms. The artifact names what you missed, preferring the hidden wing over rooms you visibly declined:

there are 12 rooms. you found 7. you did not find the ledger or the recital.

No streak. No timer. No guilt. Just an accurate sentence that happens to be unbearable to leave alone. Make returning rewarding, never make leaving punishing.

06

Three ways to write a line

This is the central design finding of the project, and it took a blunt piece of feedback to arrive at: "it's not fun yet, it's just odd."

Pools produce atmosphere

A random line from a list. Consistent, pleasant, slightly wrong hum. Pools cannot produce tension — tension requires the line to be about you, and a random pick is by definition about nobody. No amount of rewriting the pools would have closed that gap.

Stings produce tension

Twelve of them, each bound to a fact rather than to a room. A sting does not fire unless something specific and measured is true about this visitor right now.

You have been here 14 seconds. You are not reading this.
You thought about the button for 26 seconds. It thought about you for exactly as long.
Somebody said “the lamp is listening” in this room. The room is not going to say who.

↑ They said that themselves, four screens earlier.

Since "make it scarier" is unfalsifiable, the rules are explicit:

  • Specificity is the whole effect. Every sting quotes a real number. "You waited 41 seconds" is unsettling; "you waited a while" is set dressing.
  • Short. Tension does not survive a subordinate clause.
  • The turn. Benign sentence, then a pivot that recontextualises it.
  • Implication, never statement. The room never says anything frightening — it says something mundane and lets you assemble the rest. Fear you build yourself is the good kind.
  • No threats, ever. Nothing menaces the visitor or implies they are trapped. That's the horror register, and it's also the cheap one.
  • Rare. Hard cap of two per session, ~44% of eligible screens, never repeated to the same person. A shock on every screen is texture — and texture is what we already had.

Echoes produce causality

Eleven of them. A line in a later room that could only exist because of an earlier choice, sitting in ordinary prose rather than a special box.

the button is still warm. nobody has been near it. (you pressed it)
you never sat down. all four chairs are still perfect.
there are 6 chairs behind you. you still think there are 7.

Never shown in the room where the choice was made — a consequence you see immediately is just feedback.

The invariant behind all three

Nothing the room asserts is invented. Every number comes out of the event log, or the line is not shown at all. One fabricated fact and the whole effect dies on somebody's second visit.

The room is unsettling because it was paying attention — not because it is pretending to be haunted. That turned out to be the only genuinely thrilling thing a browser can do without gore.

07

The crowd, and the sentence you owe

A 4-second tick clock derived from wall time, so every observer agrees on "now" without shared state. Fifteen handle stems — someone · nobody · not you · the seventh · a held breath — and 58 ambient lines grouped by preoccupation. Handles are drawn without replacement so two bots never share a name in one window.

Real humans enter the same rail. Same handle pool, same styling, same position. "Is that a person?" stays unanswerable, and that ambiguity is the feature — a chat UI announcing itself as chat would flatten the room into a lobby.

Transport is SSE, chosen over WebSocket for zero dependencies. Each connection holds a monotonic cursor. An early version emitted only on tick change, which meant your own message never appeared — you could speak into the room and watch nothing happen.

The threshold

The only hard gate in the experience. You cannot leave until you write a sentence, and it is enforced server-side — a disabled button is a suggestion. 

Before you leave, tell us what this was like.
[ one sentence is enough                     ]
200                        GIVE IT TO THE ROOM
Everyone in the room will see this.

The answer is screened, stored, broadcast into the live rail, and written as an ordinary utterance — so it becomes material for a later visitor's recital. The loop closes: the strangers whose words get quoted at you were people standing exactly where you are standing.

A keyword classifier reads its tone, and the classifier being wrong is the mechanic, not a defect. The room is characterised as confidently, politely mistaken, so the artifact disagrees with you rather than summarising you:

you found it unsettling. the room found you very calm.
one sentence was submitted. it did not match the room's version of your visit.

There is no failure mode where a misclassification makes the product worse.

A 0.8B model with no hands

imagine runs Qwen3.5-0.8B on CPU via llama.cpp — 532 MB, quantised to Q4_K_M, --parallel 1 so the KV cache is reused. It generates the ambient voices. Flag-gated; if unreachable it falls back to the curated corpus with a loud banner and an honest /health.

repeat_penalty 1.12 · cache_prompt true

// prefilled to suppress reasoning
<think>\n\n</think>\n\n<<<LINE>>>

Prompt discipline came from KeyStone-Lite and took sentinel compliance from 2/8 to 8/8. Inference never blocks a request — an early version did, and the ending hung for over two minutes. A background pump pre-generates; the scene now renders in ~65ms.

The drawing, and a criterion that was wrong

At the end, the room is asked to draw something: "the person who just left." "Yourself." "The sound the lamp makes." Twelve subjects, several impossible. Output is palette-filtered to | - _ / \ . o ( ) [ ], capped at 5 lines, and never repaired.

The first two experiments were logged as failures. Asked for ASCII art, the model produced a markdown fence and 393 characters of underscores. Asked for a joke, it rambled for 8.4 seconds without landing one. The plan was to render everything deterministically instead.

The correction

The bar was wrong. It wasn't "is this competent" — it was "is this strange." Re-read correctly, the outputs are excellent: asked to draw a person, the model wrote out the alphabet it had been given, four times. It does not know what a person looks like, so it copied the characters. Asked to draw itself, it produced nothing at all.

A blank result is now the strongest available outcome and is counted as a success. Nothing in the code tries to make the model good at drawing. The frame does the work: a sincere attempt by something with no hands that has never seen anything.

09

Knowing things without watching

The product's central claim is that the room is strange from its own world model and never from surveillance. That constrains the data layer hard, and the constraint made the writing better rather than worse.

collectednever collected
opaque visitor + session idIP address
choices, dwell timeuser agent
what you type in the roomreferrer URL
a nine-value arrival classfingerprint, location, any third-party signal

classifyReferrer() reduces a referring URL to one of nine enum values and discards the original in the same function. A full URL can carry a username, a search query, a private group id. The class cannot. Verified: a visit from old.reddit.com/r/InternetIsBeautiful/comments/x leaves zero matches for "reddit" anywhere in the admin panel.

Platforms are never named to the visitor. Instead they're translated:

reddit → You arrived from a room inside a room. Somebody left a door open.
x / t.co → You arrived from a place where every sentence is already leaving.
search → You went looking for something and were given this instead.
direct → nothing at all. The room does not guess where you were.

Consent with teeth

Declining disables arrival classification, cross-visit memory, and any beat that references a previous visit. The visitor still gets every room. A consent dialog whose "no" changes nothing is worse than no dialog.

A cookie wall was proposed and refused. Conditioning access on consent makes the consent legally worthless — and it would have been the most exposed thing in an otherwise clean product, protecting a nice-to-have. The refusal was accepted in one message and the product got better.

The limit we will not engineer around

Cross-origin identity stitching is not implemented and cannot be. Third-party cookies are blocked or partitioned; storage is keyed by top-level site. The only remaining routes are a shared login (there isn't one) or fingerprinting (refused). So each property gets its own first-party visitor id.

Worth stating plainly, because it surprises people: Meta's pixel has exactly the same requirement. Facebook cannot observe you on a site that hasn't installed their script, and no platform sells anyone the ability to run code on facebook.com. A "unified identity" would just be a fingerprint with better branding.

10

Five bugs that passed every test

Each of these was green across the entire suite at the moment it was broken. All five were caught by a human playing the thing, or by writing a document about it.

01The hidden chair

.chair sets opacity:0 and relies on an animation to reveal it. The late chair carried style="opacity:0;animation:none". Clearing the inline opacity fell back to 0, and the inline animation:none outranked .chair.late — so arrive never played.

A chair existed in the DOM and could never be seen, while every number about it was correct: 4 visible, you counted 4, "correct at the time", difference 1. The room was telling the truth about a chair it had failed to draw.

Why the tests missed it: they counted DOM nodes. A node that exists but can never be seen counts exactly the same.
02The invisible second half

@keyframes fadeup was referenced by five rules and defined by none. All five pair it with opacity:0. An undefined animation does not run and does not warn.

Seven rooms rendered completely blank. The ledger fetched six correct numbers out of the event log and drew them into an invisible table — then offered "That cannot be right" as a response to an empty screen. The choices weren't badly written; they were orphaned from content nobody could see.

Why the tests missed it: CSS is silent about this. No warning, no exception, a page that renders "successfully."
03The silent signup

repo.addSubscriber called this.db.insert(), which does not exist — the method is put(). The route wrapped it in a catch designed to never show visitors a plumbing error, which swallowed the exception.

The endpoint returned ok:true and stored nothing. A signup form that looked like it worked and dropped every single lead — for the one thing the business model depends on.

Why the tests missed it: nothing checked the stored row. The 200 was trusted.
04The leftover message

The artifact's "Go in" was a plain href="/", which handed the browser back to the same finished session via its cookie. A second game was not a second game: same ending, same answer, threshold gate already satisfied by the previous run.

replaySession() had been correct the whole time. Nothing was calling it.

Why the tests missed it: every test started from a clean cookie jar.
05The install-only collections

sites and pixel_events were never added to COLLECTIONS. The pixel worked in testing anyway, because put() creates a collection on demand and the local database already existed.

On a fresh deploy, ensureDatabase() would not have created them. The classic install-only bug: passes everywhere except a brand new box, which is the one place nobody tests.

Found by writing the status document. Not by running anything.
11

Two patterns, and what we did about them

One rule, implemented in more than one place

The deduplication window. The chair count. The late chair. Two artifact renderers that drifted apart so the ending you saw and the ending your friend saw were different objects. Same failure, four times in one day.

The fix is never cleverness. It is one source of truth with several readers. When two stacked footers needed to avoid each other, the height became a single CSS variable read by three rules — because three hard-coded 34s would have drifted inside a week.

Verifying the producer instead of the product

A prompt was checked instead of the model's reply. Compiled source was checked instead of the actual tweet, which shipped a literal ${v.chairHint} to a real timeline. A 200 was checked instead of the stored row. HTML was grepped for text without ever asking whether any of it was visible.

What came out of it

run/smoke.sh plays three complete games over HTTP, follows whatever choices the server actually offers, answers when asked, and asserts it reaches an artifact carrying that game's own message. It cannot be a unit test — after the floorplan work there is no fixed path left to hard-code, which is precisely why a walker is the right shape.

Plus a test asserting every referenced CSS animation has a matching @keyframes, and one asserting the late chair's reveal path is reachable rather than merely present.

12

What we refused to build

"Addictive yet harmless" was the constraint that took the most thought, because the easy version of addictive is a dark pattern.

Refused, deliberately: streaks · daily-login pressure · exit guilt · FOMO timers · artificial scarcity · notification nagging · infinite scroll · sunk-cost framing · any copy that makes leaving feel like losing · a cookie wall · fingerprinting · cross-site tracking.

Used instead: a graph wider than one visit, and an accurate sentence about what you missed. Curiosity rather than compulsion — and curiosity has a floor. You can satisfy it in three minutes and be genuinely done.

Make returning rewarding. Never make leaving punishing.
13

The best idea wasn't the builder's

The counting room originally counted for you. A late chair arrived on a timer, a tally updated itself, and you were asked to agree or disagree with the result.

It read as odd rather than fun, and the reason came from the person playing it, not the person building it: nothing was at stake. The late chair was wallpaper and "agree / disagree" was a button pair with no position behind it.

The proposed fix was to reverse the order of operations:

The change

The room states its claim. You type your own number and commit it. ~1.4 seconds later, the last chair walks in. The difference is computed against your number. Only then do the exits unlock.

The answer you gave was correct when you gave it. The room never tells you you're wrong — it just quietly stops being the room you counted. That is a far better joke than the room being wrong on its own, because now it happened to you.

It also produced the strongest sting in the game — "You were right. You are no longer right. Nothing you did caused this." — and turned the artifact into a three-way disagreement worth screenshotting:

you counted 9. the room insisted on 4. it drew 3.
14

Honest ledger

Still open, and worth saying out loud:

  • ~78% of visitors touch nothing. That is the real problem and none of the recent work addressed it. The first fifteen seconds remain the weak point.
  • No og:image — shares still unfurl as plain text.
  • Live voices are in-memory; a restart clears the rail.
  • Nothing supervises the three processes.
  • The Properties admin form has been exercised by curl, never by a human hand.

A build log that only records successes is not a build log.
